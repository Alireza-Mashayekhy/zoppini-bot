# ربات مدیریتی فروشگاه Zoppini روی بله (Bale)

سرویس عملیاتی مدیریت فروشگاه Zoppini روی پیام‌رسان **بله** با اتصال امن به API اختصاصی بک‌اند NestJS (`/api/bot/v1`).

---

## ۱. معماری و امنیت

- **جداسازی کامل سرویس‌ها:** ربات به‌صورت یک پردازش مستقل Node.js 22+ بدون هیچ وابستگی خارجی (`npm`) و بدون باز کردن هیچ پورت عمومی ورودی (`long-polling`) اجرا می‌شود.
- **عدم دسترسی مستقیم به زیرساخت داخلی:** ربات به MySQL، Redis، مسیرهای `/api/admin/*` یا کوکی/توکن ادمین وب وصل نمی‌شود.
- **احراز هویت دوگانه و غیرقابل‌جعل:**
  1. احراز هویت سرویس ربات با `Authorization: Bearer <ZOPPINI_BOT_SERVICE_TOKEN>` (با مقایسهٔ زمان‌ثابت `timingSafeEqual` و پشتیبانی از چرخش بدون قطعی از طریق `ZOPPINI_BOT_SERVICE_TOKEN_PREVIOUS`).
  2. انتقال امن شناسهٔ عددی کاربر بله (`X-Bot-Actor-Id`) و نوع چت (`X-Bot-Chat-Type`) همراه با Timestamp، Nonce یکتا (محافظت در برابر Replay) و امضای `HMAC-SHA256` (`X-Bot-Signature`).
- **فقط چت خصوصی یک‌به‌یک (`private`):** پیام‌ها و کلیک‌های دکمه‌ها در گروه‌ها و کانال‌ها هم در ربات و هم در گارد بک‌اند کاملاً رد می‌شوند.
- **کنترل دسترسی مبتنی بر نقش (RBAC) در سمت سرور:**
  - `owner`: دسترسی کامل به سفارش‌ها، اطلاعات تحویل مشتری، گزارش‌های فروش و موجودی، خروجی CSV، اعلان‌ها، تنظیمات و مدیریت نقش‌ها.
  - `admin`: دسترسی کامل به سفارش‌ها (شامل اطلاعات تحویل مشتری)، گزارش‌ها و خروجی‌های CSV، بدون مجوز تغییر تنظیمات یا نقش‌ها.
  - `orders-read-only`: فقط خلاصه، فهرست و جزئیات سفارش‌ها **بدون** نمایش نام/تلفن/نشانی مشتری (فیلدهای مشتری از پاسخ API حذف می‌شوند).
  - `reports-read-only`: خلاصه و گزارش‌های فروش، موجودی، مشتری‌ها و خروجی CSV، **بدون** دسترسی به اطلاعات شخصی مشتری و بدون تغییر تنظیمات.
- **حذف داده‌های حساس (Data Minimization):** کد ملی، هش رمز عبور، پاسخ خام درگاه بانکی، IP و `user-agent` در هیچ DTO، لاگ یا رویداد Outbox قرار نمی‌گیرند.

## ۲. مستند هم‌ترازی دامنه با کد واقعی بک‌اند

1. **وضعیت‌های واقعی سفارش (`OrderStatus`):**
   - `pending`: جدید / در انتظار پرداخت
   - `paid`: پرداخت‌شده (آماده پردازش و ارسال — وضعیت مجزایی با نام `processing` در مدل داده وجود ندارد)
   - `shipped`: ارسال‌شده
   - `delivered`: تحویل‌شده
   - `cancelled`: لغوشده (سفارش‌هایی که پس از پرداخت لغو یا به کیف‌پول عودت شده‌اند، به‌صورت جداگانه از روی رکوردهای موفق `Payment` و تراکنش‌های `wallet-order-<id>-refund` شناسایی و گزارش می‌شوند)
2. **واحد پولی:**
   - موجودیت‌های `Order`، `OrderItem`، `Variant.price` و `Wallet` بر حسب **تومان (`IRT`)** ذخیره می‌شوند (درگاه‌های پرداخت و جدول خام همگام‌سازی راهکاران بر حسب ریال هستند و در مرز سرویس تبدیل شده‌اند). تمام گزارش‌ها و فایل‌های CSV واحد پول `تومان (IRT)` را صریح نمایش می‌دهند.
3. **فیلد ملاک موجودی قابل فروش آنلاین:**
   - در کل چرخهٔ ثبت سفارش، کسر موجودی، بازگردانی موجودی و همگام‌سازی راهکاران، فیلد **`variant.stock`** (در سطح واریانت رنگ/سایز) منبع حقیقت فروش آنلاین است (`stockRetail` و `stockHadishMall` صرفاً فیلدهای مرجع شعب در راهکاران هستند). تمام شمارش‌های موجودی در ربات صراحتاً بر پایهٔ **واریانت کالا** گزارش می‌شوند.
4. **الگوی تحویل اعلان‌ها (Transactional Outbox):**
   - رویدادهای سفارش، تغییرات موجودی و خطا/بازیابی همگام‌سازی راهکاران به شکل اتمیک در جدول `bot_outbox_events` با `eventId` و `idempotencyKey` یکتا ثبت می‌شوند.
   - ربات با مکانیزم Lease زمان‌دار (`POST /api/bot/v1/events/lease`) رویدادها را می‌گیرد، به گیرندگان مجاز می‌فرستد و با `POST /api/bot/v1/events/ack` تأیید می‌کند.
   - **تضمین تحویل:** چون API پیام‌رسان خارجی تراکنش دو-فازی مشترک با دیتابیس سایت ندارد، تضمین سیستم **تحویل حداقل یک‌بار (At-Least-Once) به همراه حذف تکرار عملیاتی در سطح `(eventId, recipientId)`** است؛ در تمام تلاش‌های مجدد عادی یا خطای شبکه پس از ارسال پیام، کش پایدار شناسه‌های ارسال‌شده از ارسال پیام تکراری به گیرنده جلوگیری می‌کند.

## ۳. راه‌اندازی و مایگریشن امن دیتابیس

در محیط Production مقدار `TYPEORM_SYNCHRONIZE` به‌طور پیش‌فرض `false` است و مایگریشن جدول‌های ربات (`1761465600000-CreateBotManagementTables`) به‌صورت ایمن و Idempotent اجرا می‌شود:

```bash
# در پوشه back:
pnpm build
pnpm migration:run
```

تنظیم متغیرهای محیطی بک‌اند (`back/.env`):

```env
ZOPPINI_BOT_SERVICE_TOKEN=<کلید تصادفی ۶۴ کاراکتری>
ZOPPINI_BOT_OWNER_BALE_IDS=<شناسه عددی بله مالک>
```

تنظیم و اجرای سرویس ربات (`bot/.env`):

```bash
cd bot
cp .env.example .env
# مقادیر BALE_BOT_TOKEN، OWNER_BALE_IDS، ZOPPINI_SITE_API_BASE_URL و ZOPPINI_BOT_SERVICE_TOKEN را وارد کنید
npm start
```

یا با Docker:

```bash
cd bot
docker compose up -d --build
```

## ۴. چرخش بدون قطعی کلید سرویس (Secret Rotation)

1. کلید جدید بسازید (`openssl rand -hex 32`).
2. در سرور سایت، کلید قبلی را در `ZOPPINI_BOT_SERVICE_TOKEN_PREVIOUS` و کلید جدید را در `ZOPPINI_BOT_SERVICE_TOKEN` قرار دهید و سرویس سایت را ری‌استارت کنید.
3. در سرویس ربات، `ZOPPINI_BOT_SERVICE_TOKEN` را به کلید جدید تغییر دهید و ربات را ری‌استارت کنید.
4. پس از اطمینان از سلامت ارتباط در بخش `🔔 هشدارها`، متغیر `ZOPPINI_BOT_SERVICE_TOKEN_PREVIOUS` را از سرور سایت پاک کنید.
