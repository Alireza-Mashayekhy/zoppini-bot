# بستهٔ مهاجرت ربات مدیریتی Zoppini به بله

این بسته شامل پوستهٔ Node.js ربات بله و نمونهٔ endpoint امن برای بک‌اند NestJS سایت است. این نسخه گزارش فروش، موجودی کم، خلاصهٔ مشتری و جست‌وجوی سفارش را به مسیرهای قراردادی API سایت وصل می‌کند. endpointهای سایت باید توسط برنامه‌نویس به منطق واقعی داده‌ها وصل شوند؛ تا آن زمان گزارش‌ها کار نمی‌کنند.

## شما چه کار کنید؟

1. برنامهٔ بله را باز کنید و `@botfather` رسمی را پیدا کنید.
2. دستورهای همان بازو را دنبال کنید تا بازوی Zoppini ساخته و توکن صادر شود. توکن مثل رمز اصلی ربات است؛ آن را فقط به‌صورت environment/secret امن روی سرور قرار دهید، نه در چت یا فایل پروژه.
3. پوشهٔ `bot` را به مشایخی بدهید تا روی سرور آزمایشی بالا بیاورد. در شروع، فقط `BALE_BOT_TOKEN` لازم است؛ `/start` و `/id` حتی قبل از آماده‌شدن API سایت کار می‌کنند.
4. خودتان و هر مدیر مجاز در گفت‌وگوی خصوصی با ربات `/id` بفرستید؛ عددی که ربات می‌دهد شناسهٔ بله است. ابتدا فقط شناسهٔ مالک در `ALLOWED_BALE_IDS` قرار بگیرد.
5. مشایخی باید از همان سرور اتصال HTTPS به `tapi.bale.ai:443` را تست کند. polling برای شروع به پورت ورودی جدید نیاز ندارد؛ اما درخواست خروجی سرور باید مجاز باشد.
6. پوشهٔ `site` و این README را به برنامه‌نویس بدهید تا در NestJS استفاده کند و adapter گزارش‌ها را به سرویس‌های واقعی سایت وصل کند.
7. بعد از تکمیل endpointها، مقدار secret یکسان را جداگانه در تنظیم امن سایت و سرویس ربات بگذارید. توکن بله و secret سایت دو مقدار متفاوت‌اند.
8. با مالک تست کنید: `/start`, `/id`, دکمه‌های «فروش»، «موجودی»، «مشتری‌ها» و جست‌وجوی سفارش.

## اجرای لوکال برای برنامه‌نویس

نیازمند Node.js 22 یا جدیدتر است. در پوشهٔ `bot`:

```powershell
Copy-Item .env.example .env
npm start
```

مقادیر `.env` را با مقادیر آزمایشی و امن پر کنید. `.env` نباید وارد Git شود.

## معماری اتصال

```text
بله ← HTTPS polling ← سرویس Node.js ربات
سرویس Node.js ربات ← HTTPS + service token ← API read-only در NestJS
NestJS ← سرویس‌ها و دیتابیس موجود فروشگاه
```

ربات مستقیم به MySQL/Redis وصل نمی‌شود. توکن بله فقط برای API بله و service token فقط برای API محدود سایت است.

## چه چیزهایی در این بسته هنوز production-ready نیست؟

- adapter گزارش‌های NestJS باید به سرویس‌های واقعی سفارش/موجودی وصل و با قرارداد مالی کسب‌وکار تأیید شود.
- endpoint جست‌وجوی سفارش در این نسخه با شماره سفارش خروجی محدود می‌دهد؛ شماره سفارش را مانند رمز تلقی کنید و دسترسی ربات را محدود نگه دارید.
- هشدارهای خودکار لحظه‌ای هنوز نیستند؛ برای آن outbox/queue و جلوگیری از تکرار پیام لازم است.
- گزارش قیف رفتار آماده نیست. طبق brief فعلی فقط دو صفحه tracking می‌شوند و رویدادهای کامل محصول، سبد و checkout وجود ندارند.
- دسترسی‌های ربات فعلاً allowlist مشترک دارد؛ پیش از دادن گزارش حساس به افراد بیشتر باید نقش‌های owner/admin/read-only طراحی و اعمال شوند.
