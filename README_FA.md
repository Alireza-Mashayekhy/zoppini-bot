# ربات مدیریتی Zoppini در بله (Bale)

ربات مدیریتی فروشگاه برای مدیرها در پیام‌رسان ایرانی «بله»: گزارش فروش امروز، موجودی کم، جست‌وجوی سفارش با شماره و خلاصهٔ مشتری‌های امروز — فقط در گفت‌وگوی خصوصی و فقط برای شناسه‌های مجاز.

## وضعیت فعلی

- ✅ سرویس ربات آماده است: همین پوشه (`bot.mjs`)، بدون هیچ وابستگی npm.
- ✅ API گزارش‌های سایت در بک‌اند NestJS پیاده و به داده‌های واقعی وصل شده است: `back/src/bot-reports/` (ماژول در `AppModule` ثبت شده است).
- ✅ برای هر دو سمت تست خودکار وجود دارد (`npm test` در این پوشه و `jest src/bot-reports` در `back/`).
- ⏳ فقط قدم‌های «راه‌اندازی» مانده است: ساخت ربات در بله و گرفتن توکن، تنظیم secretها روی سرور و دادن شناسهٔ مدیرها (پایین).

## معماری

```text
بله ← HTTPS polling ← سرویس Node.js ربات (bot/)
سرویس ربات ← HTTPS + Bearer service token ← API فقط‌خواندنی NestJS ‏(‎/api/bot/v1‎)
NestJS ← دیتابیس موجود فروشگاه
```

ربات مستقیم به MySQL/Redis وصل نمی‌شود. دو secret جدا داریم: **توکن بله** فقط بین ربات و بله، و **service token سایت** فقط بین ربات و بک‌اند. هیچ‌کدام نباید وارد Git، چت یا لاگ شوند.

## راه‌اندازی قدم‌به‌قدم

### ۱) ساخت ربات در بله

1. برنامهٔ بله را باز کنید و `@botfather` رسمی را پیدا کنید.
2. دستورهای همان بات را دنبال کنید تا ربات Zoppini ساخته و **توکن** صادر شود. توکن مثل رمز اصلی ربات است؛ فقط در تنظیمات امن سرور (`BALE_BOT_TOKEN`) قرارش دهید.

### ۲) ساخت secret مشترک سایت و ربات

روی سرور یک مقدار تصادفی قوی بسازید:

```bash
openssl rand -hex 32
```

### ۳) تنظیم بک‌اند سایت

در environment امن بک‌اند (همان `.env` سرور که بقیهٔ secretهاست) این مقدار را بگذارید و بک‌اند را دوباره دیپلوی/ری‌استارت کنید:

```dotenv
ZOPPINI_BOT_SERVICE_TOKEN=<همان مقدار قدم ۲>
```

بدون این مقدار، مسیرهای ربات عمداً `503` می‌دهند (fail-closed). کد این بخش از قبل در `back/src/bot-reports/` هست و کار دیگری لازم ندارد.

### ۴) تنظیم و اجرای سرویس ربات

```bash
cd bot
cp .env.example .env   # و مقادیر را پر کنید
npm start
```

یا با داکر:

```bash
cd bot
cp .env.example .env
docker compose up -d --build
docker compose logs -f
```

مقادیر `.env` ربات:

| متغیر | توضیح |
| --- | --- |
| `BALE_BOT_TOKEN` | توکن قدم ۱ (اجباری؛ بدون آن سرویس بالا نمی‌آید) |
| `ALLOWED_BALE_IDS` | شناسه‌های عددی بلهٔ مدیرها با ویرگول؛ اول فقط مالک |
| `ZOPPINI_SITE_API_BASE_URL` | مثلاً `https://zoppinico.com/api/bot/v1` |
| `ZOPPINI_BOT_SERVICE_TOKEN` | عین مقدار قدم‌های ۲ و ۳ |
| `POLLING_TIMEOUT_SECONDS` | مهلت long polling، پیش‌فرض ۲۵ |
| `BALE_API_BASE_URL` | اختیاری؛ فقط برای تست لوکال، در حالت عادی خالی باشد |

نکتهٔ شبکه: polling به پورت ورودی جدید نیاز ندارد، ولی سرور ربات باید بتواند به `tapi.bale.ai:443` درخواست خروجی HTTPS بفرستد و به آدرس API سایت هم دسترسی داشته باشد.

### ۵) فعال‌کردن دسترسی مدیرها

1. ربات را با `.env` بالا بیاورید؛ حتی قبل از آماده‌شدن API سایت، `/start` و `/id` کار می‌کنند.
2. مالک و هر مدیر مجاز در گفت‌وگوی خصوصی با ربات `/id` بفرستند؛ عدد برگشتی شناسهٔ بلهٔ آن‌هاست.
3. شناسه‌ها را در `ALLOWED_BALE_IDS` بگذارید و سرویس ربات را ری‌استارت کنید. تا وقتی شناسه‌ای در این فهرست نباشد، برای آن حساب فقط `/id` کار می‌کند.

### ۶) چک‌لیست تست نهایی

- [ ] `/start` منو را نشان می‌دهد و `/id` شناسه برمی‌گرداند.
- [ ] دکمهٔ «📊 فروش» فروش امروز را می‌آورد.
- [ ] دکمهٔ «📦 موجودی کالا» فهرست موجودی ≤ ۳ را می‌آورد.
- [ ] دکمهٔ «👥 مشتری‌ها» مشتری جدید/تکراری امروز را می‌آورد.
- [ ] «🧾 سفارش‌ها» + یک شمارهٔ سفارش واقعی، وضعیت و اقلام را نشان می‌دهد و شمارهٔ ناموجود «پیدا نشد» می‌دهد.
- [ ] با یک حساب بلهٔ خارج از فهرست مجاز، پیام «دسترسی فعال نشده» دیده می‌شود.

تست مستقیم API سایت (از سرور ربات؛ secret را در تاریخچهٔ شل نگه ندارید):

```bash
curl -s "https://zoppinico.com/api/bot/v1/reports/sales?from=2026-10-21&to=2026-10-21" \
  -H "Authorization: Bearer <ZOPPINI_BOT_SERVICE_TOKEN>"
```

## دستورهای ربات

| ورودی | نتیجه |
| --- | --- |
| `/start` یا `/menu` | منوی اصلی |
| «📊 فروش» یا `/sales` | فروش امروز (پرداخت‌شده‌ها) |
| «🧾 سفارش‌ها» یا `/orders` | پرسیدن شمارهٔ سفارش و نمایش خلاصهٔ آن (ارقام فارسی هم قبول است؛ `/cancel` لغو می‌کند) |
| «📦 موجودی کالا» یا `/stock` | واریانت‌های با موجودی ≤ ۳ |
| «👥 مشتری‌ها» یا `/customers` | مشتری جدید و تکراری امروز |
| «🔔 هشدارها» | هنوز فعال نیست (نیازمند صف رویداد در سایت) |
| «⚙️ تنظیمات» | فعلاً از روی سرور انجام می‌شود |
| `/id` | شناسهٔ عددی بلهٔ شما (برای همه آزاد) |
| `/help` | راهنمای کوتاه |

## قرارداد API سایت

همهٔ مسیرها هدر `Authorization: Bearer <ZOPPINI_BOT_SERVICE_TOKEN>` می‌خواهند و خروجی‌شان خام (بدون پاکت `{ status, message, data }`) است:

```text
GET /api/bot/v1/reports/sales?from=YYYY-MM-DD&to=YYYY-MM-DD
GET /api/bot/v1/reports/customers?from=YYYY-MM-DD&to=YYYY-MM-DD
GET /api/bot/v1/inventory/low-stock?threshold=3
GET /api/bot/v1/orders/{orderNumber}     ← پیدا نشود: ‎{ orderNumber, notFound: true }‎
```

تعریف‌های مهم گزارش (در کد هم مستند شده‌اند):

- **واحد پول تومان است (`IRT`)**: مبالغ سفارش/محصول در دیتابیس تومان ذخیره می‌شوند، پس تبدیلی انجام نمی‌شود.
- **فروش** = سفارش‌های `paid`/`shipped`/`delivered` در بازه؛ مبلغ از `finalPrice` سفارش. سفارش `pending` و `cancelled` فروش نیستند.
- **`refunds` فعلاً ۰ است**: در پروژه موجودیت مرجوعی/بازپرداخت و زمان لغو ثبت نمی‌شود، پس عدد ساختگی گزارش نمی‌شود و `netSales` برابر `grossSales` است. هر وقت رویداد مرجوعی ثبت شد، این فیلد واقعی می‌شود.
- **مشتری جدید** = ثبت‌نام در بازه (بدون حساب‌های مدیر). **مشتری تکراری** = در بازه خرید پرداخت‌شده دارد و پیش از بازه هم خرید پرداخت‌شده داشته است.
- **موجودی** = فیلد `variant.stock` (همان که با فروش کم می‌شود)، با شرط `stock <= threshold` و سقف ۵۰۰ قلم در هر پاسخ. «آخرین همگام‌سازی» تقریبِ بیشترین `updatedAt` واریانت‌هاست.
- **بازهٔ روزانه بر اساس Asia/Tehran** و ساعت دیواری دیتابیس است (همان فرض بقیهٔ پروژه).
- خروجی سفارش عمداً محدود است: نام/تلفن/ایمیل/آدرس مشتری، کد ملی، یادداشت و دادهٔ درگاه ارسال نمی‌شود. شمارهٔ سفارش را مثل رمز نگه دارید و دسترسی ربات را به همان چند مدیر محدود کنید.

## امنیت

- توکن بله و service token سایت را در Git/چت/تیکت نگذارید؛ روتشان را جدا نگه دارید و در صورت شک به افشا عوضشان کنید (توکن بله از بات‌فادر، service token با ساخت مقدار تازه در هر دو سمت).
- روی مسیرهای `bot/v1` محدودیت نرخ ۳۰ درخواست/دقیقه هست و مقایسهٔ توکن زمان‌ثابت است. در صورت امکان در لایهٔ شبکه/ریورس‌پراکسی هم این مسیر را فقط از IP سرور ربات بپذیرید.
- مسیرهای قدیمی `/api/admin/*` را به ربات ندهید؛ همین API محدود برای ربات کافی است.

## عیب‌یابی

| علامت | علت و راه‌حل |
| --- | --- |
| سرویس ربات همان اول خارج می‌شود | `BALE_BOT_TOKEN` خالی است؛ لاگ دقیقاً همین را می‌گوید. |
| فقط `/id` جواب می‌دهد | شناسهٔ شما در `ALLOWED_BALE_IDS` نیست یا بعد از تغییر، سرویس ری‌استارت نشده است. |
| ربات می‌گوید «گرفتن گزارش فعلاً انجام نشد» | لاگ سرویس ربات را ببینید: `401` یعنی service token دو سمت یکی نیست؛ `503` یعنی روی بک‌اند ست نشده؛ `404` یعنی `ZOPPINI_SITE_API_BASE_URL` اشتباه است (باید به `/api/bot/v1` ختم شود)؛ خطای شبکه یعنی دسترسی خروجی سرور ربات به سایت بسته است. |
| خطای `409` از بله در لاگ | یک نمونهٔ دیگر از ربات با همان توکن در حال polling است یا روی توکن webhook ست شده است؛ نمونهٔ اضافی را خاموش کنید. |
| ربات به هیچ پیامی جواب نمی‌دهد | دسترسی خروجی سرور به `tapi.bale.ai:443` را تست کنید؛ پیام باید در گفت‌وگوی خصوصی باشد (در گروه عمداً پاسخ داده نمی‌شود). |
| عدد فروش با انتظار مالک فرق دارد | تعریف فروش و واحد تومان را در بخش «قرارداد API» با مالک مرور کنید؛ مبالغ راهکاران/باشگاه ریالی‌اند و با این گزارش تومانی قاطی نشوند. |

## هنوز انجام‌نشده (قدم‌های بعدی)

- هشدارهای خودکار لحظه‌ای (سفارش جدید، اتمام موجودی و …): نیازمند outbox/queue در سایت و جلوگیری از پیام تکراری؛ دکمهٔ «🔔 هشدارها» فعلاً اطلاع‌رسانیِ «به‌زودی» است.
- نقش‌های جداگانهٔ owner/admin/read-only برای وقتی تعداد مدیرهای ربات بیشتر شد؛ فعلاً یک allowlist مشترک داریم.
- گزارش قیف رفتار (محصول/سبد/checkout): رویدادهای لازم هنوز در سایت ثبت نمی‌شوند.
- واقعی‌کردن `refunds` بعد از ثبت رویداد مرجوعی/لغو با زمان دقیق.
